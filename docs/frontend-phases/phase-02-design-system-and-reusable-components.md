# PHASE 02 — DESIGN SYSTEM AND REUSABLE COMPONENTS

## 1. Objective
Create a consistent GlintPM design system: colours, typography, spacing, layouts, reusable UI and interaction patterns.

## 2. Brand
- Deep green: `#085634`
- Gold: `#F3BA25`
- Cyan: `#1EC9DF`
Define supporting background, surface, text, border, success, warning, error and disabled colours. Maintain contrast and hierarchy.

## 3. Typography and Layout
Define page headings, section headings, card titles, body, supporting text, captions, buttons, labels and errors. Define screen, card, section, component and form spacing. Respect safe areas and adapt to different screen sizes.

## 4. Reusable Components
Create:
- Buttons: primary, secondary, outlined, text, disabled, loading.
- Cards: standard, course, job, resource, notification, dashboard summary.
- Forms: text, email, password, phone, selection, date, multiline, checkbox, radio and validation message.
- Feedback: loading, empty, error, success, confirmation, retry and toast/equivalent.
- Layout: screen container, section heading, page header, divider, avatar, badge and status indicator.

## 5. Component Requirements
Components must accept appropriate props, support accessibility labels and disabled/loading states where relevant, handle long text and small screens, and follow central design tokens. Avoid duplication.

## 6. Accessibility
Support screen-reader labels, sufficient contrast, touch target sizes, scalable text where practical, keyboard-friendly forms and clear validation.

## 7. Testing
Test rendering, props, interactions, inputs, loading/disabled states, screen sizes and accessibility properties.

## 8. Acceptance Criteria
Tokens centralised; reusable components implemented and branded; Android/iOS layouts responsive; accessibility considered; duplication avoided.

## 9. Deliverables
Theme, colour/typography/spacing systems, component library, tests and design-system documentation.

## 10. Final Instruction
Do not proceed until design system is ready and tested.
