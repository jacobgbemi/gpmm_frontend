# GlintPM Mobile App — UI/UX Guidelines

## 1. Design objective
Create a professional, clear, mobile-first experience for learners and project professionals. Prioritize clarity, trust, and ease of completing key tasks.

## 2. Brand palette
- Primary green: `#085634`
- Gold accent: `#F3BA25`
- Cyan accent: `#1EC9DF`

Use neutral background and text colours that maintain sufficient contrast. Do not use accent colours for large areas without checking readability.

## 3. Main navigation
Use five primary areas:
1. Home
2. Learn
3. Career
4. Resources
5. Support

Use clear labels and consistent icons. Do not rely on icons alone where a label improves comprehension.

## 4. Screen guidance

### Home
- Welcome and account context.
- Continue-learning card where relevant.
- Course progress summary.
- Featured career opportunities.
- Featured resources.
- Announcements and notifications.
- Clear shortcuts to main areas.

### Learn
- Course categories.
- Course cards with title and concise description.
- Delivery mode and relevant cohort details.
- Course detail page with track, price, schedule, and enrollment status.
- Clear distinction between free and restricted content.

### Career
- Search and filter controls.
- Readable job cards.
- Employer, location, job type, and date information where available.
- Clear external application action.
- Saved-jobs access.

### Resources
- Resource categories.
- Search.
- Resource type and access level.
- Clear open/download action.
- Explain access restrictions.

### Support
- Explain available support categories.
- Keep enquiry form fields clearly labelled.
- Use appropriate input types and validation.
- Display submission confirmation and next-step information.

## 5. Component standards
Create reusable components for:
- Buttons.
- Text inputs.
- Dropdown/select controls.
- Course cards.
- Job cards.
- Resource cards.
- Section headings.
- Empty states.
- Loading indicators.
- Error messages.
- Confirmation messages.

## 6. Interaction standards
- Show visible feedback after important actions.
- Prevent repeated submissions while a request is processing.
- Confirm destructive or consequential actions.
- Make navigation predictable.
- Provide clear back navigation.
- Avoid unnecessary animations.

## 7. Form standards
- Label every field.
- Identify required fields.
- Provide useful validation messages.
- Preserve user input when recoverable errors occur.
- Show server-side validation errors near relevant fields.
- Do not indicate success until the backend confirms success.

## 8. Responsive behaviour
- Test on small and large supported phone screens.
- Avoid fixed widths that cause clipping.
- Respect safe areas.
- Support keyboard interaction and scrolling.
- Ensure buttons and fields remain reachable when the keyboard is open.

## 9. Accessibility
- Use accessible labels and roles.
- Maintain readable contrast.
- Support screen readers for key workflows.
- Do not communicate status by colour alone.
- Use sufficiently large touch targets.

## 10. Content tone
Use clear, professional, plain language. Avoid exaggerated promises, vague claims, and unnecessary jargon. Training and career outcomes must be described accurately and must not imply guaranteed employment.
